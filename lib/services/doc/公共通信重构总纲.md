# 公共通信重构总纲（v2.0，规划阶段）

## 0. 文档目的与范围

本文是 AWLF 公共通信体系的唯一治理源，用于统一“原则、边界、阶段、验收、变更控制”。  
本文属于规划文档，不包含实现级接口与数据结构定义。

> 分层总依赖矩阵以 `awlf/document/architecture/分层与依赖规范.md` 为唯一规范源。本文仅补充公共通信专项治理规则。

本文覆盖：

- 公共通信层在 AWLF 中的职责边界
- 规划阶段的阶段目标与门禁条件
- 跨文档治理关系与口径一致性规则
- 证据化决策与停点机制

本文不覆盖：

- 结构体、函数接口、枚举、参数级设计
- 单一 BSP/板卡实现细节
- 协议字段逐字节定义

## 1. 治理模型（唯一规范源）

## 1.1 文档治理关系

1. 本总纲是唯一治理源，定义规则与边界。
2. `分册1_公共通信中间件设计.md` 只定义架构规划，不重复治理规则。
3. `公共通信基础设施技术方案.md` 只定义基础设施技术方案与设施归属矩阵，不定义治理规则。
4. `公共通信工程落地规划.md` 只定义工程执行分解、阶段门禁与回滚策略，不定义治理规则。
5. 规划路线与文档资产要求统一在本总纲第 4 章定义。
6. 其他文档仅允许“专项补充 + 引用”，不得改写本总纲结论。

## 1.2 规划阶段产出约束

1. 允许：原则、能力、路线图、风险与验收口径。
2. 禁止：实现接口、具体类型、字段/参数设计。
3. 所有实现决策必须显式标注“实现阶段冻结”。

## 2. 顶层原则（冻结）

## 2.1 分层单向依赖原则

1. 应用层不得依赖 CAN bank/filter/mailbox 等板级细节。
2. 外设驱动层不得反向依赖公共通信层语义。
3. 公共通信核心仅依赖 core/osal/sync/async 基础层，不依赖具体驱动实现。
4. 总线接入适配逻辑位于实现端，保持核心层与板级细节解耦。

## 2.2 职责收敛原则

1. 公共通信层负责通用通信语义与路由分发能力。
2. 驱动层负责硬件收发与设备状态，不承载业务路由语义。
3. 协议层/业务层负责领域语义，不下沉到通信核心。

## 2.3 实时路径原则

1. 中断路径只允许有界、可审计的最小处理。
2. 复杂匹配与分发在可调度上下文执行。
3. 慢消费者不得反向阻塞中断入口。

## 2.4 演进与回滚原则

1. 采用阶段化演进，阶段之间有明确门禁。
2. 新链路通过验收前，不替换现有稳定业务路径。
3. 每阶段必须保留回滚路径与证据。

## 3. 架构边界（规划层）

目标分层关系：

```text
vendor_drv -> bsp -> drivers(peripheral core) -> comm_adapter(impl) -> services/comm(core) -> protocol/service -> app
```

边界约束：

1. `services/comm(core)` 不感知板级资源分配细节。
2. `comm_adapter(impl)` 只承担总线到通信语义的接入转换。
3. BSP 仅提供硬件能力，不承担公共通信路由策略。

## 4. 规划阶段路线图

## 4.1 阶段划分

1. Phase G0（治理收敛）  
目标：形成唯一治理源与文档职责分工。

2. Phase G1（能力规划）  
目标：形成系统级基础设施能力域矩阵、工程设施清单与缺口优先级。

3. Phase G2（实现准备）  
目标：冻结实现前输入条件与验收框架，进入接口设计阶段。

## 4.2 阶段门禁（Gate）

G0 通过条件：

1. 三份文档职责边界无冲突。
2. 规划文档无实现级类型/接口内容。

G1 通过条件：

1. 基础设施关键能力域均有“现状-目标-缺口-优先级”。
2. 每个关键决策均有证据化对照。
3. 规划文档与技术方案文档已分离存放。
4. AWLF 补充设施与通信中间件内部设施的边界已冻结。
5. 异步与观测落位口径已冻结（`lib/async` + `lib/osal`）。

G2 通过条件：

1. 实现阶段输入完整且无关键歧义。
2. 验收指标、风险控制、停点机制均可执行。

## 4.3 文档资产与交付

本阶段必须交付：

1. 治理文档：`公共通信重构总纲.md`
2. 架构分册：`分册1_公共通信中间件设计.md`
3. 技术方案：`公共通信基础设施技术方案.md`
4. 工程规划：`公共通信工程落地规划.md`

## 5. 证据化决策规则

关键决策必须使用“决策-证据对照表”，至少包含：

1. 决策点
2. 参考框架来源
3. 吸收内容
4. 不采纳内容
5. 适配 AWLF 的理由

参考范围（规划阶段）：

- Zephyr（zbus/message queue/workqueue/poll）
- Linux（SocketCAN/lockless ring buffer/PREEMPT_RT）
- AUTOSAR（Layered Architecture/COM/PduR）
- ROS2/DDS（QoS）
- NATS（Pub/Sub + Req/Rep）
- libuv（event loop）

## 6. 停点机制（强制）

遇到以下任一情况必须停点：

1. 规划目标与分层规则冲突
2. 能力矩阵缺少关键基础能力但无法补齐优先级
3. 验收口径无法量化或不可观测
4. 跨文档出现口径冲突且无法归并

停点输出格式：

1. 事实与证据
2. 影响范围
3. 可选方案与权衡
4. 需要确认的决策项

## 7. 验收口径（总纲层）

本总纲完成标准：

1. 三份文档形成“唯一治理源 + 专项补充”关系。
2. 规划阶段内容与实现阶段内容边界明确。
3. 关键决策具备证据化来源与取舍说明。
4. 阶段门禁可执行、可审计、可复用。

## 8. 术语（规划层）

1. 公共通信核心：面向跨总线统一语义的核心层。
2. 接入适配层：位于实现端的总线接入转换层。
3. 中断入口路径：从硬件中断进入通信体系的最短路径。
4. 规划冻结：仅冻结原则、能力与路线，不冻结实现接口。
