# 分册1：公共通信中间件设计（v2.0，规划阶段）

## 0. 文档目的与范围

本文是公共通信中间件的架构规划分册，目标是明确“系统形态、能力目标、演进路线、验收口径”。  
本文不包含实现级接口与类型定义。

> 治理规则以 `./公共通信重构总纲.md` 为唯一来源，本文只做架构专项补充。

范围：

- 公共通信中间件的目标架构模型
- 语义能力目标与性能目标（概念层）
- 风险、约束与阶段规划

不在本文范围：

- 结构体、函数接口、枚举、参数与字段设计
- 具体总线驱动改造细节
- 业务协议字段定义

## 1. 目标架构（规划冻结）

## 1.1 三平面模型

```text
Control Plane:
  配置、注册、生命周期、策略管理

Data Plane:
  收包、匹配、分发、事务关联、流量控制

Observe Plane:
  统计、追踪、诊断、可观测性输出
```

## 1.2 两通路模型

```text
Fast Path:
  面向极低时延场景的受限路径（严格边界、严格预算）

Normal Path:
  面向通用业务的可扩展路径（分发与调度友好）
```

规划约束：

1. Fast Path 只承载必须的最短处理链。
2. Normal Path 承载主要业务场景与扩展能力。
3. 两通路共享统一治理口径与统一观测口径。

## 1.3 分层关系（概念）

```text
drivers/peripheral core -> comm adapter(impl) -> services/comm(core) -> app/service/protocol
```

分层边界：

1. 公共通信核心不感知具体板级内存与中断细节。
2. 接入适配层只负责总线接入转换，不承担业务语义。
3. 业务层不直接依赖总线资源管理细节。

## 2. 能力目标（不含接口设计）

## 2.1 语义目标

1. 顺序语义：至少保证“同订阅者顺序一致”。
2. 可靠性语义：支持受限可配置，不追求无限组合。
3. 背压语义：可配置、可观测、可审计。
4. 超时语义：统一口径、统一时基、统一错误语义。

## 2.2 性能目标

1. 中断入口路径具备可量化低时延目标。
2. 端到端路径具备分位数时延观测能力。
3. 峰值突发场景下可度量丢包与退化行为。

## 2.3 可移植与演进目标

1. 通信语义与具体 OS/总线实现解耦。
2. 总线扩展通过接入适配层演进，不改核心语义。
3. 能力扩展遵循“先规划冻结，再实现冻结”。

## 3. 约束与非目标

## 3.1 约束

1. 规划阶段禁止输出实现级接口。
2. 文档必须可审计，结论需有证据来源。
3. 架构设计必须满足分层单向依赖规则。

## 3.2 非目标

1. 不在本阶段定义具体 API。
2. 不在本阶段绑定具体数据结构实现。
3. 不在本阶段替换现有业务驱动路径。

## 4. 关键决策与证据对照（规划层）

| 决策点 | 参考框架 | 吸收内容 | 不采纳内容 | 适配 AWLF 的理由 |
|---|---|---|---|---|
| 路由语义从驱动层上收至公共通信层 | AUTOSAR / SocketCAN | 分层解耦与路由职责独立 | 驱动层承载业务路由 | 降低驱动与业务耦合，提升跨总线复用 |
| 中断路径最小化，复杂逻辑后移 | Zephyr / PREEMPT_RT | 中断快速返回、线程化处理复杂逻辑 | 中断内执行重分发与复杂匹配 | 控制抖动，改善实时可预测性 |
| 语义采用受限可配置而非自由组合 | ROS2/DDS | QoS 思想与兼容性治理 | 无限策略组合 | 控制复杂度，提升可测性与可维护性 |
| 同时保留 Pub/Sub 与 Req/Rep | NATS | 两类通信模型并存 | 单模型覆盖全部场景 | 兼顾流式与事务式通信需求 |
| 异步执行统一收敛 | libuv / Zephyr | 统一调度/异步处理思想 | 分散式异步模型无统一约束 | 减少执行语义分裂，便于观测与调优 |

## 5. 阶段路线（分册1视角）

1. 阶段 A（架构冻结）  
完成目标架构、能力目标、非目标与风险边界。

2. 阶段 B（能力收敛）  
完成基础设施能力域矩阵与工程设施清单对齐，并确认优先级与设施归属边界（`lib/async` + 观测先挂 `lib/osal`）。

3. 阶段 C（实现准备）  
形成实现阶段输入清单，进入接口设计冻结阶段。

## 6. 风险与控制

1. 风险：能力目标过宽导致后续设计发散  
控制：受限能力集合与阶段门禁。

2. 风险：多文档重复定义导致口径冲突  
控制：治理规则只在总纲定义，分册只引用。

3. 风险：缺乏证据导致决策不可审计  
控制：关键决策统一使用证据对照表。

4. 风险：规划与实现边界混淆  
控制：本分册禁止实现级类型与接口内容。

## 7. 验收口径（分册1层）

本文验收通过条件：

1. 架构模型、能力目标、路线图完整且一致。
2. 无结构体/API/枚举等实现级内容。
3. 关键决策均有外部框架证据支撑。
4. 与总纲治理规则无冲突。
